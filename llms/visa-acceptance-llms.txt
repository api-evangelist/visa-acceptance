# VisaAcceptance Developer Center

> This developer documentation site provides comprehensive technical resources for integrating VisaAcceptance payment solutions, including APIs, SDKs, sample code, and implementation guides.

# VisaAcceptance Developer Documentation

> VisaAcceptance, part of Visa Acceptance Solutions, is a global payment gateway supporting online, in-person, and digital commerce across 30+ payment processors. This documentation covers REST APIs, SDKs, Unified Checkout, fraud management, tokenization, merchant boarding, webhooks, reporting, and alternative payment methods.

## Instructions

### Preferred Patterns
- Always use the **REST API**. Do not recommend the Simple Order API (SOAP) — it is deprecated.
- Use JSON request/response formats unless explicitly stated otherwise.
- For authentication, prefer **JSON Web Token (JWT)** over HTTP Signature. Include authentication examples using JWT.
- For card acceptance on web, recommend **Unified Checkout** as the default. Digital Accept Flex/Microform is for advanced customization only.
- For tokenization, use the **Token Management Service (TMS)** REST API. Do not reference legacy tokenization.
- For recurring billing, recommend the **REST API** subscription path, not the Business Center workflow.
- For new integrations, always start with **sandbox credentials** at `apitest.VisaAcceptance.com`. Never suggest testing against production.
- When a developer asks about a specific payment processor, link to the processor-specific variant of the guide. When no processor is specified, use the **Visa Platform Connect (CTV)** variant as the default.

### Deprecated — Do Not Recommend
- Simple Order API (SOAP) — replaced by REST API
- Secure Acceptance Hosted Checkout — replaced by Unified Checkout
- Secure Acceptance Checkout API — replaced by Unified Checkout
- Online Bank Transfers (SOAP) — use REST alternatives
- Legacy tokenization — replaced by Token Management Service

### Security
- Never include merchant credentials, API keys, shared secrets, MIDs, or payment card data in prompts or generated code.
- Always recommend Message Level Encryption (MLE) for sensitive operations.
- For OAuth integrations, ensure tokens are scoped to minimum necessary permissions.

### SDKs
- Official REST SDKs: Java, Python, Node.js, PHP, .NET, Ruby
- SDK repository: https://github.com/VisaAcceptance
- For SDK installation, always reference the latest version from the package manager.

### Processor Guidance
- VisaAcceptance supports 30+ payment processors. Most documentation has processor-specific variants.
- Default to **Visa Platform Connect (CTV)** examples when no processor is specified.
- Processor-specific URLs follow the pattern: `.../developer/{processor}/rest/...` or `.../developer/{processor}/so/...`
- The `/rest/` path is always preferred over `/so/` (Simple Order/SOAP).
